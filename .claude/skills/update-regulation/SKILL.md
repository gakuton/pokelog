# レギュレーション更新スキル

pokelog の使用可能ポケモン・持ち物データを、新しい対戦レギュレーションに合わせて更新する手順。

引数でレギュレーション名(例: `M-D`)が渡されていなければ、まずユーザーに確認する。
以下では `M-D` を例に、文字部分を `D`、小文字を `d` として説明する。

## 0. 前提

- ネットワークアクセスが必要(Bashでのcurl、WebFetch、WebSearch)。
- `yakkun.com` は Cloudflare で直接アクセスできない。`https://r.jina.ai/<元URL>` を
  WebFetch (または `curl`) に渡すことでバイパスできる。
- `gamewith.jp` は直接curlで取得できる。

## 1. 新規追加ポケモンの特定

1. `python3 scripts/extract_gamewith_additions.py D` を実行する。
   - デフォルトURLは `https://gamewith.jp/pokemon-champions/546414`(内定ポケモン一覧ページ)。
     もしページ構造が変わっていて `id="newD"` のアンカーが見つからない場合は、
     WebSearchで「ポケモンチャンピオンズ 内定ポケモン一覧 gamewith」を検索し、
     最新のURLを第2引数で渡す。
   - それでも失敗する場合は、`https://yakkun.com/ch/zukan/reg_md/` を
     `r.jina.ai` 経由でWebFetchし、ページ内の追加ポケモン名を聞き出す。
2. 出力されたリストには、メガシンカ形態(例: 「メガ◯◯」「メガ◯◯Z」)や、
   既存ポケモンの新メガ対応(例: 既存ポケモンにメガが追加された場合、そのポケモン名自体が
   リストに再掲される)が混ざる。次を踏まえて整理する:
   - 既に `public/data/pokemon_master.json` に存在する名前は「新規追加」から除外する
     (ただしそのポケモンに新しいメガが追加された可能性があるので、`has_mega` フラグと
     対応するメガストーンの有無は要確認)。
   - 「メガ◯◯」「メガ◯◯Z」のような接頭辞つきエントリは、ベースとなるポケモン名の
     `has_mega: true` の根拠として扱う。ベース名自体が別途リストにあるか確認する。
   - 性別違い(オス/メス)・フォルム違いは既存データの命名規則(例: `イエッサン(オス)`、
     `ライチュウ(アローラ)`)に合わせて別エントリにする。見た目だけの色違い
     (イキリンコの羽の色等)は1エントリにまとめる(既存の `ビビヨン` と同じ扱い)。
3. 整理した「純粋な新規ポケモン名リスト」をユーザーに一度提示して認識を合わせる。

## 2. タイプ・種族値の特定

1. 各新規ポケモンの全国図鑑番号を特定する(既知の知識でよいが、自信がなければWebSearch
   「◯◯ ポケモン 図鑑番号」で確認する)。
2. `scripts/data/national_dex_cache.json` の `entries["<図鑑番号>"]` を参照する。
   - 同じ番号に複数エントリがある場合、フォルム/性別/メガ違いが順に並んでいる。
     文脈(オスが先かメスが先か等)で正しいものを選ぶ。迷ったらWebSearchで確認する。
   - キャッシュが古く該当データが無い、または `national_dex_cache.json` 自体が
     直近で更新されていない場合は `python3 scripts/refresh_national_dex_cache.py`
     を実行してから再度参照する(ネットワークが必要)。
3. タイプの表記は既存 `pokemon_master.json` に合わせる(例: `ノーマル`,`ほのお`,`みず`,
   `くさ`,`でんき`,`こおり`,`かくとう`,`どく`,`じめん`,`ひこう`,`エスパー`,`むし`,`いわ`,
   `ゴースト`,`ドラゴン`,`あく`,`はがね`,`フェアリー`)。
4. `public/data/pokemon_master.json` の末尾に新規エントリを追記する
   (`name`, `types`, `base: {hp,atk,def,spa,spd,spe}`, `has_mega`)。

## 3. 持ち物の更新

1. `https://yakkun.com/ch/item.htm?mode=reg_md` を `r.jina.ai` 経由でWebFetchし、
   新規追加された持ち物(通常アイテム・メガストーン)一覧を取得する。
2. `lib/const.ts` の `HELD_ITEMS` と突き合わせ、既存に無いものだけを追記する
   (`// ── M-D 新規追加 ──` のようなコメント区切りを付ける、既存の書式に倣う)。
3. メガストーンは対応するポケモンの `has_mega` フラグが正しく `true` になっているか
   ステップ2と合わせて確認する。既存ポケモンに新メガが追加された場合はそのポケモンの
   `has_mega` も更新すること。

## 4. 検証

1. `npm run build` を実行し、型エラー・ビルドエラーが無いことを確認する。
2. 変更点(追加ポケモン、修正したhas_mega、追加アイテム)をユーザーに一覧で報告する。

## 5. 反映

- コミット・push は必ず `AskUserQuestion` でユーザーに確認してから実行する。
  無断でpushしない。

## 既存データの全件再検証について(このスキルの対象外)

このスキルは新規追加分の反映のみを行う。既存ポケモンのタイプ・種族値を全件
再検証してほしいとユーザーから明示的に依頼された場合は、以下の方針で対応する:

- `scripts/data/national_dex_cache.json` を突合先として使い、`pokemon_master.json`
  の全エントリ(200件超)を名前→図鑑番号→タイプ/種族値の順で照合する。
- トークン消費が大きいので、Agentツール(`subagent_type: "fork"`)に委任し、
  修正結果のサマリーのみを受け取る。
